## 1. Executive summary

1. Knowledge = one Cosmos container `KnowledgeBase` (pk `/businessId`, `CORE\Cosmos\Setup\CosmosContainerPolicies.cs:743-782`) holding `KnowledgeDocument` registry rows (one per uploaded file or typed FAQ) and `KnowledgeServiceDraft` rows; passages ("cards") live in the Azure AI Search index `clinket-knowledge{-env}` (alias → physical `-v1`), one card per ~350-token chunk (`CORE\Entities\AISearch\KnowledgeSearchDocument.cs`); originals, extracted images, thumbnails, the parsed-content artefact and OCR page cache live in the private blob container `provider-knowledge`.
2. The index HAS a per-card `pageNumber` (Int32?, retrievable ONLY — not filterable/sortable) plus `sectionTitle` (heading path ≤3 deep) and `chunkKind`; it has NO page range, table id or heading-path array. Page numbers are real only for Document-Intelligence sources (PDF/photos/TIFF: `<!-- PageBreak -->` counting) and PPTX (slide number); DOCX/XLSX/HTML/TXT/JSON cards carry the block default `1`, FAQ/overview cards carry `null`.
3. Retrieval today is ONE hybrid Azure Search request (BM25 over 6 fields + vector k=10 on `contentVector`, pre-filter) with filter `businessId eq '{id}' [and (linkedServiceIds/any(...) or not linkedServiceIds/any())] [and hasEmbedding eq true]`, plus a parallel "overview companion" query, per-document fairness, a live "retrievable docIds" allow-list from Cosmos, and a 3000-token payload trim — all inside `INFRA\Services\Knowledge\ProviderKnowledgeSearchService.cs`, with four isolation layers (scope-led filter, `AssertScoped`, per-row businessId verify that throws, Cosmos allow-list). No LLM, no scores exposed, no relevance cutoff.
4. The ONLY caller today is the MCP voice tool `search_knowledge` (`MCP\Tools\KnowledgeTools.cs:79-117`) + the expert-check synergy (`INFRA\Services\Voice\ProviderCatalogAnswerService.cs:360-375`); the in-app chat cannot call it (`Mcp:ChatToolAllowlist` excludes it, `MCP\appsettings.json:197-214`).
5. The owner's "checkbox" is `KnowledgeDocument.ShareWithCallers` (default true) — it governs SENDING (send_material_info refs), NOT retrieval: a switched-off document is still searched and spoken. Per-image `Sendable` + a `Deleted` tombstone govern picture sends. There is NO per-document "hide from the AI"/internal-visibility flag today (**NOT FOUND**).
6. Images: extracted at ingest, content-addressed (`imageId` = SHA-256[..16]), stored at `{businessId}/_images/{docId}/{imageId}.ext`, captioned once by vision (luna), thumbnail (320px) via the media-derivative queue; provider UI gets read-SAS URLs ONLY from `GET api/v1/knowledge/documents/{docId}/images` (SAS lifetime = `InternalSasExpiryMinutes` 60, one storage round trip per URL).
7. Source files: stored at `{businessId}/{docId}/{filename}` in `provider-knowledge`; **NOT FOUND**: any API/web/mobile path that returns a view/download URL of the original to the provider (only Document Intelligence receives a read SAS internally).
8. Service index (`clinket{-env}`) has `businessId` (filterable, lowercase-normalized), `categoryId`/`subcategoryId` (filterable), `categoryName`/`subcategoryName` (searchable+filterable+facetable), `serviceId`, `serviceName`, `businessFriendlyName`, `isActive`, `businessStatus`; the MCP catalog lookup scopes with `businessId eq '…' and isActive eq true and businessStatus eq 'Active'`. No `approvalStatus` field on the index document (**NOT FOUND**; gating happens at index time).
9. Cost hot-spots per search: 1 embedding call (Interactive lane), 2 search requests, 1–3 partition-scoped Cosmos queries (`ListRetrievableDocIdsAsync` always; ref gates only when `IncludeRefs`), zero LLM. Per SAS URL: one storage round trip (`EnsureContainerExistsAsync`).
10. Hosts: MCP host registers `IProviderKnowledgeSearch`; API host has `KnowledgeSearchClient`, `IEmbeddingService`, `IAICompletionService` but does NOT register `IProviderKnowledgeSearch`/`ICatalogAlarm` (**NOT FOUND** in `API\Program.cs`).
11. Several memory/skill statements are stale vs code (RetrievalMaxTokens 1500→3000, searchFields 4→6, `id` now sortable, Images kill switch deleted, artefact unconditional, method renamed `ListRefSuppressedDocIdsAsync`) — listed in §2.5.6 and §2.9.

## 4. Gaps / risks / open questions

Page-number availability (for "document + page" citations):
- `pageNumber` exists on every card but is (a) NOT selected on the search path today (`ProviderKnowledgeSearchService.cs:52-56`), (b) only meaningful for DI-paginated sources (PDF/photos/TIFF/BMP/HEIF) and PPTX (slide), (c) a misleading constant `1` for DOCX/XLSX/HTML/TXT/MD/JSON (block default, `KnowledgeBlocks.cs:33`), (d) `null` for FAQ/DocSummary/DocAggregate cards. A UI must branch on the row's `SourceKind`/blob extension (or `PageCount == null`) before printing "page N"; for DOCX/XLSX use `sectionTitle` (heading/sheet) instead. Any page-RANGE for a card spanning pages is **NOT FOUND** (only the start page); paragraphs that cross a PageBreak keep the page they started on (`KnowledgeDocumentParser.cs:154-160, 262`).
- Retrieval hands the model composed text, never card ids/docIds/page numbers; a citation UI needs a new result shape (or `GetByRefsAsync` per hit, which costs a second search request) — no code change to the INDEX is needed for page/doc citations, only to select/DTO.
- No relevance score or reranker score is surfaced; "None" is decided only by zero hits after allow-listing, so a web UI cannot show confidence today.

Cross-tenant guardrails that exist (reuse, do not re-invent): scope-led filter + `AssertScoped` + `PreFilter` + per-row verify-and-throw + Cosmos retrievable allow-list (§2.5.3); the businessId must come from the authenticated business context (`GetCurrentBusinessId()` in the API, `CallContext` in MCP) — `KnowledgeSearchQuery` cannot carry it by design. New risk for a web search endpoint: the API host has no `IProviderKnowledgeSearch`/`ICatalogAlarm` registration (**NOT FOUND**, `API\Program.cs`) — a registration + an API-side alarm implementation would be new code; the MCP alarm is MCP-specific.

Visibility model:
- Only `Ready`/not-`Deleting` gates retrieval; `shareWithCallers` and per-image `sendable` gate SENDING only. A "hide this document from the AI" / per-role internal visibility flag does not exist (**NOT FOUND**) — adding one is a §0.7 Cosmos-field change (or a repurpose decision for `shareWithCallers`, which would change today's voice semantics: switched-off documents are still spoken). The natural retrieval hook is `ListRetrievableDocIdsAsync` (fail-closed allow-list already applied after search).
- `search_knowledge`/`send_material_info` are excluded from the chat allowlist; the in-app chat gateway exists only where `Mcp:PublicUrl` is configured ("CA-only Clinqet.Mcp server", `CORE\Interfaces\AI\IMcpToolGateway.cs:9`) — an India provider using MCP-routed tools from the web would run toolless.

Cost hot-spots:
- Per query: embedding (Interactive) + 2 search requests + 1-3 Cosmos partition queries + a session CAS write (voice). Semantic ranking is off (billed per query, measured negative).
- Per rendered image: one SAS mint = one `EnsureContainerExistsAsync` round trip; 60-min SAS; a grid of 40 originals at 2048 px is tens of MB — prefer thumbnails (320 px) and mint lazily (the existing images endpoint already does).
- Ingestion is the expensive side (DI per page, vision per unique image at luna/Medium/1500 tokens, describer, embeddings, 40 thumbnails per doc) — a search feature adds nothing there unless it reprocesses.
- RU: `KnowledgeDocument.Images` array (≤40 entries) rides every point read of the row; `ListSendableImageRefsAsync` uses an ARRAY subquery to keep the wire payload to ids (`KnowledgeDocumentRepository.cs:219-230`).
- Passage payload ≤ 3000 tokens per call is the real LLM-input lever (`RetrievalMaxTokens`); topK 8 does not raise it (SKILL:1185-1213).

Data-quality / rendering caveats for an HTML answer page:
- Stored `content` is BODY only; the header must be composed with `KnowledgeCardPrefix` or the reader sees an orphan passage (`KnowledgeSearchDocument.cs:69-71`).
- Table cards are `label: value | label: value` one record per line (no HTML, `KnowledgeChunker.cs:981-1009`); `MaterialExcerptBuilder.ParseRecordLine` shows how to re-tabulate (`MaterialExcerptBuilder.cs:308-331`).
- Prose overlap (15% trailing sentences) repeats across adjacent cards; `MaterialExcerptBuilder.DropOverlap` handles it (406-438).
- Provider-authored text is sanitized only for control characters (`SanitizePassage`) — prompt-injection through uploaded documents is acknowledged and unmitigated (`MEM\knowledge-image-audit-session2-2026-08-27.md:169-176` / thumbnail memo item 1 deferred).
- Language: documents keep their language; the voice prompt instructs English queries; a multilingual provider UI should not assume the card language equals the UI language (`language` field is filterable per document).

Operational:
- Index alias probes need a recent api-version (2026-04-01) — an SDK concern only; a `select` naming an undeclared field 400s the whole query (why `imageRef` must exist in the index before binaries select it).
- `Ready` is never re-validated against the index; after ANY index rebuild every document must be reindexed (`knowledge-health` + `reindex-knowledge` admin endpoints).
- Two live regions (CA/IN) each own an index/container/blob set; `cosmosindexsetup` must be run per region with `--launch-profile` (SKILL:2074-2076).

Open questions for the planner:
1. Should `shareWithCallers=false` documents be searchable by the provider's own team in Provider AI Search (they are searchable by the voice AI today)? If a stricter internal-visibility flag is wanted, it is a new Cosmos field (§0.7) — decide before design.
2. Where should the new search endpoint live — API host (needs `IProviderKnowledgeSearch` + `ICatalogAlarm` registrations) or the MCP host via the chat gateway (needs `Mcp:ChatToolAllowlist` additions and is CA-only today)?
3. Citation shape: extend `KnowledgePassage` (voice contract, pinned by tests) or introduce a separate provider-facing result record carrying `docId`, `chunkNo`, `pageNumber`, `sectionTitle`, `imageRef`, and `blobPath`-derived download URL (which itself does not exist yet — a new read-SAS endpoint for the source file would be new code with a TTL decision)?
4. Score exposure: do we want `@search.score`/`@search.rerankerScore` for the UI (not read anywhere today; semantic ranking measured negative for voice)?
