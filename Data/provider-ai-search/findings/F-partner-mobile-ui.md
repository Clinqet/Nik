## 4. Gaps / risks for a faithful mirror

1. **No markdown renderer.** Options (both are NEW dependencies → owner approval + `package-lock` + native build check): (a) `react-native-markdown-display` (JS-only, themeable per token) — or (b) convert markdown→HTML (also needs a parser; none installed) and render with the already-installed `react-native-render-html@6.3.4`, which has **no table plugin** here and renders headings only as styled as `policyHtmlStyles` says. Inline images inside markdown would need custom renderers in either route. Streaming markdown re-parses the whole answer on every chunk — budget the parse (debounce renders; the Knowledge screen already uses `useDebounce`).
2. **Streaming helper is single-purpose.** `streamSetupOnce` hard-codes the provider-setup endpoint semantics (`data:` JSON frames only, 330 s stall, no caller cancel/`AbortSignal`, `xhr.abort()` only from the stall path, no `event:` field support, no 403→AccessDenied, no 429/`Retry-After`, no observability headers, English fallback strings in `handleRequest`). A chat-style stream needs: a short stall (seconds), a cancel handle, token-chunk frames, terminal `done`/`error` frames, and the same 401/403/429 contract as `fetchWithAuth`. `xhr.responseText` is re-read on every `onprogress` — O(n²) string copies for long answers; keep answers bounded or track the offset carefully (the `consumed` pointer already avoids re-parsing).
3. **Background/foreground.** RN suspends JS timers in background (`AnalyticsProvider.tsx:15`); iOS suspends the XHR — a stream that spans a backgrounding will stall; design a "regenerate/continue" state. The `AppState` listener pattern exists (`Knowledge/index.tsx:15`, SKILL `:25-27`).
4. **Copy-to-clipboard.** RN core `Clipboard` is deprecated with a removal warning (`react-native/index.js:238-245`); a "copy answer" action means adding `@react-native-clipboard/clipboard` (native → Mac build) or reusing the deprecated core API as the three existing call sites do.
5. **Document viewing.** No PDF/document viewer, no download, no read-SAS endpoint for a whole document (`constant.tsx:215-241`), and the Knowledge route has no `docId` param — a citation "open document, page N" cannot be honoured today. Minimum: add `Knowledge: { docId?: string }` (`types.ts:149`) + highlight/scroll-to-row, and mirror the web route (`dashboard/profile/knowledge/:docId` only if web serves it — AASA parity, `deepLinking.test.ts`). Opening the original would need a server read-SAS + `Linking.openURL` (as chat attachments do) or an in-app browser (`react-native-inappbrowser-reborn` is installed).
6. **Images.** Knowledge image URLs are short read-SAS (`knowledgeService.ts:70-71, 160`); inline answer images need fresh URLs at render time, `DerivativeImage` for fallback, and there is no cache layer (RN `Image` memory cache only) and no pinch-zoom viewer. Three-across grid rules exist (`knowledgeImagesStyle.ts:81-88`) if the answer shows an image strip.
7. **Permission model.** No `SURFACE_PERMISSIONS`/`gateOn` key describes an AI-search surface; the closest precedent is `voice.read` for Knowledge/VoiceAssistant (`gatedScreens.tsx:71-72`). Choosing/adding a permission is a backend + web-rules decision (owner ask); mobile then regenerates `renderingRules.ts` and fixtures.
8. **Five-file registration + web parity + locales ×5.** New route = `constant.tsx`, `types.ts`, `linking.ts` (only if web has the path; AASA excludes otherwise), `MyDashboard-Route.tsx`, `analyticsTracker.screenMap`, a visible `navigate()` entrance, `en/es/fr/gu/hi.json` keys (nested, `_one/_other`, no ICU, no `defaultValue`), and analytics verbs that already exist on web (`analyticsWebParity`).
9. **Onboarding escape.** If reachable from any wizard screen, take `entryContext` and gate every navigation through one guarded function with a count-pinning test (§2.10).
10. **Fonts/dark mode.** `Lufga` is not bundled — weights ≥700 for bold; never `brandBlue` as text in dark (`ui.tsx:98`); 44 bare hex literals still lack dark counterparts and no screen has had a 390 pt device run (SKILL `:721-722, 876-877`).
11. **Lists.** Knowledge renders rows via `ScrollView.map`; a results/messages list should use `FlatList` (`ChatDetails` precedent) with a `KeyboardAvoidingView` composer (`ChatDetails/index.tsx:1362-1365`).
12. **Speech component literals.** `SpeechToTextButton.tsx:63, 70, 81` carry English strings — localize (the AST guard misses conditional expressions).
13. **Working tree.** Another session's uncommitted Knowledge edits are live in this repo (11 files) — coordinate; never restore via git (§0.19).
