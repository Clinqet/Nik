## 2. FIXED — HIGH

**H1 · A fail-OPEN enum fallback in the audience allow-list.** `KnowledgeDocumentRepository.ListSearchVisibleDocIdsAsync`
resolved an unparseable `searchAudience` to `Team` — the *most permissive* value. On a rolling deploy that
introduced a third audience value, hosts still on the old build would hand the **most restricted** documents
to the **whole team**. Worse, the two surfaces disagreed on the same row: the raw-string projection resolved
it while the typed entity's `StringEnumConverter` **threw** (HTTP 500).
**Fixed:** unknown ⇒ `Roles` with no keys (owner/administrator only) in the repository, and a new
`KnowledgeSearchAudienceConverter` on the entity that fails closed identically, so both surfaces agree.
Absent still means `Team` (the approved default). **Test:** `AnUnrecognisedAudienceValue_IsTreatedAsOwnerAndAdministratorOnly`
(real Cosmos; patches a literal `"BranchesOnly"` onto the stored row and asserts both surfaces).

**H2 · Disposing the SSE enumerator while a `MoveNextAsync` was in flight.** Proven by probe on net10.0:
`DisposeAsync` on a suspended async iterator throws `NotSupportedException`, which (a) replaces the real
exception and (b) **skips the iterator's own `finally`**. The agent's producer was therefore never cancelled:
it sat on a full 100-slot bounded channel with no reader, holding an open Azure OpenAI SSE response and an
admission lease, for up to `TotalTimeoutSeconds` (150 s) *after the request had already returned*. A genuine
client disconnect was also logged as "Business Search failed".
**Fixed:** the pending step is tracked and awaited (`ConfigureAwaitOptions.SuppressThrowing`) in a `finally`
before the enumerator is disposed.

**H3 · A model-leg timeout ended the stream with NO terminal frame.** The model leg has its own shorter clock
(`Answer:TimeoutSeconds` 60) inside the whole-answer budget (`TotalTimeoutSeconds` 150). Its cancellation
matched neither the budget filter nor the client filter, so it fell into a catch that only logged — the client
received a 200 `text/event-stream` that simply closed. That is exactly the "spinner that ends in nothing" this
feature forbids. **Fixed:** a dedicated `when (!cancellationToken.IsCancellationRequested)` catch writes the
partial-answer/timeout terminal frame.

**H4 · Either daily-counter order burns the wrong allowance — and one enables a team-wide lockout.**
Incrementing the member counter first burned a member's allowance on a *business*-cap refusal. Reversing it
(my first fix) was worse: a member who had exhausted their own 60 could spend **6 business units a minute** at
the burst limit and exhaust the business's 200/day in ~34 minutes, locking out every colleague until UTC
midnight. **Fixed:** read both counters first and refuse a caller already over either ceiling without spending
anything; then increment-then-compare for the exact boundary race. Residual, documented in code: one unit,
once, for the caller who crosses the line on that very request. This also gave `GetBusinessCountAsync` /
`GetMemberCountAsync` their production caller (see R3).

**H5 · A hardcoded English string reached the member's screen.** `"All services"` (the global-offer sentinel)
was rendered verbatim as a citation subtitle. It was invisible for years because on the voice path the model
*speaks* the value and therefore translates it; a citation card is rendered by the client, untouched.
**Fixed:** the sentinel is now `FullProviderContextService.GlobalOfferScope`, and `ListOffersTool` swaps it for
`BusinessSearch_Citation_AllServices` — added to all five language files (3141 → 3142 each).

**H6 · The audience allow-list is a full-partition read, re-run on every `search_knowledge` call.** Roughly
150–400 RU per call on a 200-document library, against ~1 RU for the point reads that actually feed the answer,
and four calls in one answer meant four identical scans. **Fixed:** memoized for the lifetime of the request
(the service is scoped, and the authorization is fixed for the turn by construction). A `ReadFailed` is
deliberately *not* cached, so a transient Cosmos failure cannot poison the request.

## 6. NOT FIXED — needs an owner decision (§0.7 or scope)

**O1 · ‼️ CLOSED BY THE OWNER (2026-09-02): NOT A DEFECT, no action. Kept below for the record only.**
Follow-up turns replay answer PROSE, which is never re-authorized. `AUTHORIZATION-DESIGN` §3.8 and
`PLAN` §10.7 require that only opaque handles cross a turn and that sources are re-resolved each turn. The
implementation persists and replays the assistant's finished text (capped at `SessionTurnMaxChars`, TTL 7
days), and `GET sessions/{id}` returns it directly. If a document is restricted, a role downgraded, or a
member removed between turns, the withdrawn content is still in context and still readable.
**Why not fixed here:** the correct fix records each turn's source docIds and re-resolves them on load.
`AiConversationTurn` has **no** free-form bag (unlike `AiSession.Metadata`, which is what let `membershipId`
avoid a schema change), so this needs either a §0.7 field or a deliberate encoding into `AiSession.Metadata`
aligned with a list that `Trim()` also trims. **Owner decision requested.**

**O2 · `MaterialExcerptBuilder` was not reused (S3).** S3 required either `Build(...)` or a deliberate
widening *with a stated reason*. Neither happened; the tool uses raw `Clean(...)`. **Stated reason now, for
the owner to accept or reject:** the builder's useful members are private/internal and only `Build(...)` is
public, and its output shape is tuned for the caller-facing PDF excerpt rather than a screen snippet. Reusing
it means widening its surface. Recommend doing so in P2 alongside the renderer.

**O3 · "Link, not a download" is unmet for `.docx/.xlsx/.html/.txt`.** Those types store a placeholder page,
so "Show page N" is never offered, and S1 then correctly forces `Content-Disposition: attachment`. Net for a
`.docx`: passage plus the download the owner explicitly refused. The cheap fix (a "Show section" level built
from stored chunk text — no new storage, no egress) is in no phase's scope.

**O4 · Six live dashboard surfaces were declared out of scope by the plan, not by the owner** — call
follow-ups (the receptionist's own call summaries), billing, ai-billing, activity, notifications,
refund-requests. Against "everything about my business … I could be asking anything". Call follow-ups is one
tool with an existing permission key.

**O5 · A permission refusal is indistinguishable from "nothing found".** An unheld tool is dropped from the
model's list, so nothing downstream knows a money/offers question was asked and the model answers with rule
3's "I couldn't find anything". §9b promises fixed localized copy. Fixing it means either keeping a
declared-but-refusing schema entry, or classifying the question server-side before the model runs — a design
choice, not a bug fix.

**O6 · The solo → first-hire transition silently opens the archive.** Every document defaults to
"Everyone on my team"; when a solo provider hires their first member, the whole archive is immediately
searchable by them. Recurs for every provider, forever.

**O7 · A minted read-SAS is not revocable** for its 10-minute life — it survives an audience change, a role
downgrade and member removal. S1 limits this mostly to PDFs. Record as an accepted residual or stream bytes
through the API.

**O8 · ‼️ PARTLY CLOSED — the 7 missing dials were ADDED at their exact class defaults (read from
`VoiceCatalogSettings.cs`, not guessed), so runtime behaviour is unchanged and they are now tunable. The 3
DIVERGENT values still need the owner intent.**
`Voice:Catalog` in the API host was missing 7 dials that the Business Search path reads
(`EmbedThreshold`, `MapMaxCategories`, `MapMaxSubcategoriesPerCategory`, `MapExamplesPerSubcategory`,
`MapExampleNameMaxChars`, `MapSampleSize`, `MaxLookupsPerCall`) and three others diverge from the MCP/Functions
values (`LookupSlowWarnMs` 1500 vs 2500, `IndexCoverageMinRatio` 0.9 vs 0.5, `CosmosFallbackMaxScan` 400 vs
200) with no stated reason. Values currently equal the class defaults, so tuning them elsewhere silently does
not apply here. **Needs the owner's intent** before I pick numbers for a third host.

**O9 · ‼️ PARTLY CLOSED — the hardcoded literal is now the `BusinessSearch:ServiceLookupSource` dial,
default `Cosmos` (today behaviour, unchanged). Whether to actually switch to the index is still open.**
The service AI Search index is registered and never queried. `SearchServicesTool` hardcodes
`VoiceCatalogSource.Cosmos`. The owner asked to query "our AI, our knowledge index **and our service index**".
The cost rationale is sound; the divergence is unrecorded and the literal is a hardcoded enum where §0.12
wants a dial.

- S7 · CAS treats `Gone` as retryable ⇒ **first run STILL GREEN — the guard was BLIND.** No test covered
  the `Gone` path at all. A test was added that asserts the **attempt count is 1**, not merely that the call
  returns false — returning false is also what an exhausted retry loop does, so a return-value-only assertion
  would have passed either way. Re-run: **RED**, 1 failure. This is the third guard in this programme that
  looked correct and proved blind until it was actually broken.

**A fixture that was lying.** Applying the image prefix guard turned `SearchKnowledge_ShowsAPictureWhoseCallerSendableTickIsOff`
RED, because the fixtures used `"doc1"` as a docId — a shape this platform never stores. Real docIds are
canonical 32-character ids, which is exactly what the guard checks. The guard was right and the fixture was
unfaithful; all of that file's ids are now canonical. **A test passing against data production cannot produce
is not evidence.**

## 12. ‼️ THE TRUTHFULNESS CLASS — found after the audit closed, and why the audit missed it

> The owner flagged this as the most dangerous kind of defect in the feature, and they are right: every one of
> these makes the assistant state something **false, confidently, to the business's own team**. A wrong answer
> that looks uncertain is a nuisance. A wrong answer that looks complete is a decision made on bad information.

### 12.1 The defect that started it

`search_services` consumes `IProviderCatalogSearch`, a service written for the **phone receptionist**. Its
result carries `VoiceCatalogOutcome` — **four** values: `Matches`, `TooBroad`, `None`, `Unavailable`.

When a search matches more rows than one answer should list, the shared shaper returns `TooBroad` with a
**3-row sample** (`TooBroadPreviewCount = 3`) and a note reading *"Too many to read out. Do NOT list them."*
— correct for a caller who cannot be read a list.

`SearchServicesTool` named exactly **one** of those four values (`Unavailable`) and inferred the rest from
`Offerings.Count == 0`. So `TooBroad` fell through the `Matches` path: **3 services were handed to the model
as the complete catalogue, with the true total (e.g. 47) never reaching it.** A provider asking "what drainage
work do we do?" was answered with three, definitively.

### 12.2 Why the audit missed it — three compounding reasons, stated plainly

1. **The dimensions were organised by CONCERN, not by SEAM.** Ten agents audited correctness, isolation, cost,
   leaks, config, localization, tests, deployment, coverage. **Nobody was tasked with "for every pre-existing
   service this new code calls, enumerate the states it can return and prove each one is handled."** The defect
   lives precisely at the boundary between new code and reused code, which is nobody's dimension.
2. **An if-chain over an enum gets no compiler help.** A `switch` expression on `VoiceCatalogOutcome` would
   have warned about unhandled cases. Two `if` statements produce silence. The correctness agent read the file
   and reported 23 findings — it simply did not follow the call into the voice service to discover that a
   fourth outcome even existed.
3. ‼️ **The test fixtures encoded the same blind spot as the code.** Every mock of `IProviderCatalogSearch`
   returned `Matches` or an empty list. **No test ever produced `TooBroad`,** so no test could fail. This is
   the deepest lesson: a suite built from the same mental model as the implementation cannot find the
   implementation's blind spots — it inherits them.

### 12.3 The full sweep — every instance of the class, and its status

The sweep asked one question of the whole feature: **"is anything handed to the model, or to the member, that
is partial, bounded, filtered or failed, without saying so?"**

| # | Where | What was wrong | Status |
|---|---|---|---|
| C-1 | `SearchServicesTool` | `TooBroad` sample answered as the complete catalogue | **FIXED** — the true total, the number shown, and an explicit "not the full list" note now reach the model |
| C-2 | `GetBusinessProfileTool` — `addresses` | capped at 25 **silently** (introduced by me earlier this session) | **FIXED** |
| C-3 | `GetBusinessProfileTool` — `serviceAreas` | capped at 25 **silently** | **FIXED** |
| C-4 | `GetBusinessProfileTool` — `locations` | capped at 25 **silently** | **FIXED** |
| C-5 | `GetAvailabilityTool` — `otherLocations` | capped at 25 **silently** | **FIXED** |
| C-6 | `ProviderKnowledgeSearchService.SearchForProviderAsync` | the audience allow-list was applied **after** the search window, so a restricted member whose visible documents ranked below invisible ones was told *"your documents do not cover that"* — **a false negative stated with confidence**, while a document that DID answer sat just outside the window | **FIXED** — the allow-list is pushed into the query filter, so the window fills with documents the member may actually see |
| C-7 | `SerializeCapped` | dropped tail rows silently | **FIXED earlier** — emits `truncatedForLength` |
| C-8 | agent — `finish_reason: length` | truncated answer presented as complete | **FIXED earlier** — `PartialAnswer` status |
| C-9 | agent — token window exhausted mid-answer | bare `Done` on a half-written answer | **FIXED earlier** |
| C-10 | agent — model-leg timeout | stream closed with **no terminal frame at all** | **FIXED earlier** |
| C-11 | retrieval — failed registry read | would have read as "nothing found" | **FIXED earlier** — the three-state `ReadFailed` ⇒ `Unavailable` |

**Checked and clean:** `SearchKnowledgeTool` handles all three `VoiceKnowledgeOutcome` values explicitly
(`Unavailable`, `None`, `Passages`) — that seam was already complete. `.Take(8)` on narrowing hints and
`.Take(kept)` on citations are correct by design: hints are not the answer, and citation alignment is what
keeps cards matched to what the model actually read.

### 12.4 The guard that now makes this class fail loudly

A behavioural `[Theory]` enumerates `Enum.GetValues<VoiceCatalogOutcome>()` and asserts each value produces a
**distinct and honest** payload — `Unavailable` sets the unavailable flag, `None` says nothing found,
`TooBroad` carries the true total and the sample warning, and `Matches` carries **none** of that hedging.
Its `default` arm calls `Assert.Fail`, so **adding a fifth outcome to the shared enum fails this test**
with an explanation, which is exactly the alarm that did not exist.

A source-scanning guard was rejected deliberately: the tool source lives in `clinqetinfrastructure` and the
test in `clinqetapi`, and §0.17 forbids a test reading another repository. The behavioural form is legal,
runs in-process, and is strictly stronger — it proves the handling, not merely the presence of a keyword.

### 12.5 Sabotage — all four new guards proved RED

| Sabotage | Result |
|---|---|
| S8 · `TooBroad` falls through to the `Matches` path (**the original bug, reproduced exactly**) | **RED** — 2 failures |
| S9 · trimmed lists handed over silently | **RED** |
| S10 · the allow-list is not pushed into the query filter | **RED** |
| S11 · a search is issued even when nothing is visible | **RED** |

### 12.6 The rule this produces, for every later phase

> ‼️ **When you consume a service built for another channel, you inherit its whole contract — including the
> result states you did not think of.** Before calling one: enumerate its outcome enum, and handle or
> explicitly reject every value. Then build a fixture for **each** value, not only the happy one.

### 13.1 ‼️ O8 re-derived from the call sites — the first analysis was wrong

The owner refused an alignment-for-consistency answer and asked what each value actually does, with **accuracy
first, then cost and performance equally**. Reading the call sites overturned the earlier recommendation:

| Setting | What it ACTUALLY does | Verdict |
|---|---|---|
| `CosmosFallbackMaxScan` | **INERT.** One use site: `Limit = Math.Min(LookupTooBroadThreshold + 1, this)`. With the threshold at 8, the limit is 9 — this value never binds at anything ≥ 9. 400 and 200 are identical. | Set to **200** for consistency; it is a guard rail that never fires |
| `IndexCoverageMinRatio` | **INERT on this surface.** Only `ResolveSourceAsync` reads it, and Business Search passes its source explicitly, so the probe never runs. If the Index leg is ever enabled, 0.9 is the accuracy-favouring posture. | **Kept at 0.9** |
| `LookupSlowWarnMs` | **Logging only** — a warning when a lookup was slow but succeeded. Zero effect on accuracy, cost or latency. A typed answer's first token waits on this lookup, so the tail is worth seeing earlier than on a phone call. | **Kept at 1500** (deliberately tighter than voice) |

**The real find was a setting nobody asked about.** `LookupTooBroadThreshold` = **8** is a PHONE number — a
caller cannot be read a list. On a screen it meant "what do we offer in <category>?" was answered with a
3-row sample for any business with more than 8 matching services. Raised to **25** for the API only:

- **Accuracy** — the common catalogue question now answers in full.
- **Cost** — `Size = threshold + 1` on the SAME single partition query: 26 small rows instead of 9. Single-digit
  RU, no extra round trip.
- **Prompt safety** — bounded downstream by `ToolResultMaxChars` + `SerializeCapped`, which trims the tail
  and now REPORTS the trim, so the prompt cannot grow without limit.
- **Readability** — 25 rows render comfortably as a markdown table.

Voice, Functions and MCP keep 8. Only the API's own `Voice:Catalog` section changed.
