### ‼️ Do not push until the number-lifecycle shell is on master

These templates are inert without `EmailShell` and the `Content` property. Once that session has pushed, the
branches must be rebased onto it — and that rebase cannot be done in `C:\Nik`, because checking the branch out
there would overwrite the other sessions' uncommitted files (§0.19). Use a worktree:

```bash
git -C C:/Nik/clinqetshared fetch origin
git -C C:/Nik/clinqetshared worktree add /tmp/w-shared feature/email-modernisation
git -C /tmp/w-shared rebase origin/master      # keep THIS side on EmailShell.cs / EmailTemplate.cs
git -C /tmp/w-shared rev-list --merges origin/master..HEAD   # must print nothing
```

Repeat for `clinqetinfrastructure` and `clinqetfuncations`, re-run
`dotnet test Clinqet.Communications.UnitTests`, then push libraries first:

```bash
git -C C:/Nik/clinqetshared push origin feature/email-modernisation:master
git -C C:/Nik/clinqetinfrastructure push origin feature/email-modernisation:master
git -C C:/Nik/clinqetfuncations push origin feature/email-modernisation:master
```

### Deploy order

Templates ship as content of every host that sends mail, so `clinqetapi`, `clinqetfuncations` and
`clinqetidentity` must all be deployed from the same build. A host still running the old `Clinqet.Shared` would
read a `Content` template into a model that has no `Content` property and send a blank email.
