# Functions host (`Clinqet.Communications`): runtime binding settings audit (dev, CA + IN)

Date 2026-10-02. Read-only: nothing in Azure or in any repo was changed.

## Verdict

Both deployed apps (`clinket-functions-ca-dev` in `functions-ca`, `clinket-functions-in-dev` in `functions-in`; Flex Consumption, Linux, dotnet-isolated 10.0) are **up**: host state `Running`, host 4.1054.250. But **6 of 90 functions are in error in BOTH regions**, because 6 binding settings were never applied to either app. The Functions host's own per-function status says so for each one: `'%X%' does not resolve to a value`. A sweep of all 180 function slots (90 x 2) found 168 clean and exactly these 12 in error.

## How the host resolves these settings (rules, with evidence)

1. **Binding expressions `%A:B%` are resolved by the Functions HOST, never by the worker.** The host's name resolver reads the host configuration: app settings (environment variables) in Azure, and `local.settings.json` `Values` under Core Tools.
   - `A:B` maps to the environment variable `A__B`.
   - On Linux (both apps are Linux Flex), an app setting name cannot contain `:`, so **only the `A__B` form works**.
   - **`appsettings.json` is not a host source.** `Program.cs` lines 85-88 add it to the *worker's* `builder.Configuration` only.
   - The same rule is written in three places: the csproj comment ("the Functions host reads local.settings.json BEFORE the .NET worker starts, so trigger bindings ... cannot be layered through IConfiguration"), the settings-class comments in `PaymentReconciliationFunction.cs`, `SubscriptionBillingSchedulerFunction.cs` and `UsageAggregatorFunction.cs` ("HOST-resolved ... NOT this class"), and deploy.ps1 lines 8589-8591.
   - Not live-provable here, because no binding key exists only in `appsettings.json`. The only two that appear there, `CosmosDb:ContainerNames:Transactions` and `Tenancy:Lifecycle:ExpirySweepCron`, are also app settings.
2. **A missing binding setting fails only that function (partial host startup).** This is proven live: the host is `Running`, 84 functions run, and the 6 return `Error indexing method 'Functions.X' ... does not resolve to a value`.
3. **`Connection = "X"`.** Host extensions per the build's `extensions.json`: Service Bus `Microsoft.Azure.WebJobs.Extensions.ServiceBus` 5.17.0 (worker package 5.24.0) and Cosmos `Microsoft.Azure.WebJobs.Extensions.CosmosDB` 4.15.0 (worker 4.15.0). Timer and HTTP are built into the host.
   - The WebJobs connection lookup tries `AzureWebJobsX`, then `X`, each as `ConnectionStrings:X` or a plain setting.
   - A string value is a connection string. A section with children is identity-based: Service Bus needs `X__fullyQualifiedNamespace`, Cosmos needs `X__accountEndpoint`. `X__credential` and `X__clientId` are optional; the system-assigned identity needs neither.
   - This lookup order is from the WebJobs SDK and was not re-read from source in this audit.
   - Both apps carry `ServiceBusConnection__fullyQualifiedNamespace` and `CosmosDbConnection__accountEndpoint`. The plain `ServiceBusConnection` and `CosmosDbConnection` are absent on purpose: deploy.ps1 line 7530 removes them.
   - The Cosmos triggers set no `LeaseConnection`, so the lease container uses `CosmosDbConnection` and `%CosmosDb:DatabaseName%`. `CreateLeaseContainerIfNotExists = true` cannot create a container through data-plane RBAC, but the lease container already exists: both change-feed functions are clean.
4. **Platform settings.**
   - `AzureWebJobsStorage` serves as host storage (the timer monitor for `UseMonitor = true`, singleton locks, and the function key for `TwoFactorDeliveryReport`, which is `AuthorizationLevel.Function`). It is also the Flex deployment-storage credential: `functionAppConfig.deployment.storage.authentication` is `StorageAccountConnectionString` with setting name `AzureWebJobsStorage`. It is present in both apps.
   - `FUNCTIONS_WORKER_RUNTIME` and `FUNCTIONS_EXTENSION_VERSION` are **correctly absent**. On Flex Consumption the runtime comes from `functionAppConfig.runtime` (dotnet-isolated 10.0).
   - `DeviceRegistrationRetry` uses a literal cron (`0 */15 * * * *`), so it needs no setting.
   - The text `%setting%` inside a code comment in `SearchIndexSyncFunction.cs` is not a binding, and deploy.ps1's guard regex also ignores it.

### Binding settings deploy.ps1 does NOT write

**None.** All 69 are written by the live apply and listed as required. The gap is that deploy.ps1 (and `events.json`) have not been applied since these were added. It is not a gap in the script.

### Caution: fix by re-running deploy.ps1, not by hand-adding the six keys

Two things go wrong if someone sets only the six keys by hand.

**1. Two of the six functions still will not work.** `InsightsRollup` and `VoiceNumberOperationProcessor` would move from "indexing error" to a listener error, because their queues do not exist. Both queues need the `events.json` deployment.

**2. Other settings deploy.ps1 writes are also absent from BOTH apps.** None of these blocks startup, but they change behaviour once the functions run:

- **`Discovery__DefaultCurrency`.** deploy.ps1 L8209 sets `CAD` (CA) or `INR` (IN), and the key is in the required list at L2284.
  - Absent, the worker falls back to `appsettings.json` `USD`.
  - deploy.ps1's comment says the Functions host issues past-booking invoices in this currency when neither the booking nor the business names one. That is the comment's claim; the code path was not traced in this audit.
  - Along with the six binding keys, this is the 7th key in deploy.ps1's own required list that is absent from both apps.
- **`VoiceNumbers__MaxMonthlyRental`, `MaxSetupFee`, `RateCurrency`, `IdleNumberBuffer`, `SelfServiceAllocationEnabled`, `AutomaticReturnEnabled`** (deploy.ps1 L6235-6244). Absent, the worker uses the `appsettings.json` defaults: `1`, `1`, `USD`, `10`, `false`, `false`.
  - On **CA dev** these defaults match what deploy.ps1 would set.
  - On **IN dev** they do NOT. deploy.ps1 sets `2.50`, `0`, `PLIVO` and `0`.
  - If `VoiceNumbers__LifecycleSchedule` and the operations queue were fixed alone on IN, the money-path number lifecycle would run with Telnyx/USD caps against Plivo prices.
- **`MALLOC_ARENA_MAX`** = `2` (deploy.ps1 L7554, memory tuning for PDF rendering).
- **`ClinketApi__InternalApiKey`** is absent, but deploy.ps1 writes it only when `-SignalRInternalApiKey` is passed (L7695). The worker therefore uses the committed `appsettings.json` value, which passes the Program.cs startup check at L1182.
- Other keys deploy.ps1 writes only when a parameter is passed (Telnyx, 2Factor, Mailchimp, Geocoding, Stripe, Razorpay, Payments promo knobs) are also absent. They were **not judged** here.
