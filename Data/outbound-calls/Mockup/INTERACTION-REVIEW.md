## Campaign creation: return paths and draft ownership

The five steps are **Goal → People → Conversation → Timing & budget → Review & test**. They form one draft. Small choices stay inline. Tasks needing a separate preview or multi-step work open an overlay on desktop/tablet and a sheet in the native preview; the underlying step and fields stay in place.

| Task | Open and return behavior | Required working integration |
|---|---|---|
| Use a saved brief | A picker inside Goal; review its full content; Back returns to the list; Close returns to Goal | Load the business's reusable briefs; apply the selected brief's goal, completion outcome, points, questions, formats and actions; retain the selected audience, files, voice and timing; clearly disclose which fields are replaced |
| Help me draft | Describe the desired conversation and purpose → review an editable suggestion → Apply to my campaign | Real drafting service; user's input informs the suggestion; bounded structured result with goal, completion outcome, points, questions and actions; loading/retry/error with input retained; no automatic permission, approval or launch |
| Review calling permissions | Overlay inside People; review each person's exact reason; optional permission-link task stays inside the overlay stack | Live per-number/business/purpose eligibility; permission evidence and stop provenance; actual permitted consent-send flow; send does not mark consent granted; blocked people remain excluded; return preserves audience and wizard step |
| Choose information | Three labeled checkboxes directly in Conversation; changes immediately update the draft and selected count, without opening a dialog or requiring Save selection | Use the actual assistant knowledge catalog and receptionist-access rules; persist the exact selected IDs and enforce the subset in every retrieval/send/render seam specified in PLAN §15.2; whole knowledge files are never sent |
| Add / choose / edit a handout | Within Conversation; upload → actual preview → approval → attach; nested library and file views have Back; the root view has one Close control | Real upload, content/type/size checks, preview, approval, attachment, edit/copy, unlink, protected delete and sending eligibility; do not make the user abandon campaign creation |
| Review calling hours | Compact counts → View people & hours expands inline; search/filter/page → open a person for their hours and source | Show actual business settings, bounded pages, effective local window and source/status per recipient; editing defaults, if offered, must preserve the draft and apply actual rules |
| Leave campaign | With unsaved changes: **Keep editing / Discard changes / Save draft & leave** | Save the entire draft before navigating; on failure remain in the builder with edits intact; Continue saved draft restores the step and every field; browser/native back and deep links use equivalent protection |
| Close an edited supporting dialog | Warn only about unsaved dialog changes; Keep editing restores the actual entered values | Preserve text, selections and chosen file while confirming; discarded dialog edits must not discard or alter the campaign draft |

Opening a supporting overlay requires no “leave page” warning because it does not abandon the campaign. Applying a replacement brief explicitly identifies the fields being replaced. Closing a read-only picker simply returns. Actual full-page navigation requires draft protection. If implementation chooses a dedicated page for a tool, carry a real return destination and draft ID, show **Back to campaign**, restore the same step and retain the same protection; generic history alone is insufficient.

The ambiguous “One engine. A clear task.” card has been removed. “Help me draft” means assistance writing the conversation, rather than a tone setting or permission decision. “Use a saved brief” is a starting-point action, rather than a third calling purpose.

## Conversation: horizontal sections with a clear job

1. **Guide the conversation:** talking points and questions side by side on wide screens, stacked on narrow screens. Add and remove actual items. Preserve edited text, required/optional behavior, answer types and choices. Required means always ask when appropriate; it never forces the customer to answer. Validate empty items and choice lists, and render confirmed/refused/unknown outcomes accurately.
2. **Choose what the assistant can do:** explicit booking, rescheduling, cancellation, details, selected handout and team follow-up permissions. These controls bind to real tool restrictions, rather than only changing the displayed checkmark.
3. **Information for answering questions:** the three current choices are directly visible as responsive checkbox cards. All are selected by default; Select all restores them. Changes update the draft immediately; at least one source is required before continuing. No extra open/save/close sequence. For a genuinely large catalog, retain all-by-default and use a bounded searchable inline expansion, with exact selected IDs preserved across pages. Business information and files sent to a customer have different jobs.
4. **Files to share with customers:** current attachments with View & edit and Remove, plus Add a handout and Choose from library. File approval is separate from attachment and permission to send.
5. **Language & voice:** same supported-language catalog, recommended voices, remaining voices, descriptions, selection and independent Play/Stop samples as AI Assistant settings. Native uses the existing compact chosen-voice card and a scrollable full voice sheet; web shows the voice cards inline. Optional speaking-style guidance follows the voice choices. All choices appear in Review & test and the saved brief.

The isolated preview uses the currently verified catalog: English, French, Spanish, Hindi, Punjabi and Gujarati; Marin and Cedar recommended, followed by Alloy, Ash, Ballad, Coral, Echo, Sage, Shimmer and Verse. Production loads the real option catalog, preserves its order and recommendation metadata, uses the line/campaign's language for samples, stops previous audio on voice/language change and navigation, and exposes loading, failure and retired-choice states. Selecting and previewing are distinct actions; keyboard arrows change the selection silently. Preserve the actual AI settings' persona limit and semantics.

## Handout safety: unlink, edit and delete are different operations

**A HANDOUT USED BY ANOTHER CAMPAIGN MUST NOT BE DELETED OR OVERWRITTEN FROM THIS CAMPAIGN.** “Remove from this campaign” only detaches this draft's reference. It leaves the shared library file, every other campaign's reference and past delivery history intact. The file view names other campaigns that use it and explains the protection next to the disabled Delete control.

Editing a shared file creates an independent copy with a new review/approval; the original remains unchanged. A replacement upload always needs fresh approval. A file unused by other campaigns may be edited or deleted deliberately, subject to permissions and frozen brief/delivery references. Deletion is never permission to erase another campaign's history or break an immutable used brief. Past deliveries remain auditable.

**Enforce protection on the server as well as in the UI.** Recheck ownership, references and versions at write/delete time, including a concurrent attachment by another campaign. A stale UI must receive a clear conflict and retain the file. Do not infer safety solely from a displayed campaign count. Phase 3 implements the handout lifecycle and protection; Phases 4–5 bind it and prove matching web/native behavior. Necessary schema decisions follow AUT-1 and IMPLEMENTATION-CHARTER.md: document current need, alternatives and cost, then proceed without routine approval. This design does not invent existing storage fields or routes.

The preview demonstrates an actual local PDF/image preview for selected files, an explicitly labeled example file, required approval, a shared protected file, edited copies, unlinking and deletion of an unused file. Draft saving stores the preview data in this browser and reports storage failure rather than pretending to save. Production uses authoritative storage and a persisted draft identity.

## Timing and budget: explain the rule where it is used

“Next allowed time” means that launch makes calls eligible to be scheduled; it does not dial every person immediately. “Schedule a start” is a not-before time in the provider's displayed zone. The expiry date also names that zone. Each person is then called only within their own effective local window and before the earlier campaign/brief/booking deadline.

The per-person preview shows the time zone, its source/status, local days/hours and any hold. PLAN §8 governs the derivation: contact address first; supported phone area code otherwise, using the intersection of allowed hours for multi-zone codes; India uses IST; unknown is held without guessing. Legal envelope, brief window and optional business opening hours are intersected; daylight saving is resolved at dial time. A phone area code is a constrained fallback, not a promise that the customer's current physical location is known. Implementation shows the actual basis and recomputes eligibility, rather than assigning “confirmed” to every contact.

The budget label, value, hint and bounds use the normal readable form surface. Only the estimate is on a navy panel. Changes to target duration update the estimate; schedule, expiry, target duration, hard limit, voicemail and cap persist and appear in Review & test. Validate a complete start, ordered deadlines within the allowed lifetime, target ≤ hard limit, and the live available minutes. Retry/frequency enforcement comes from the scheduler; decorative explanatory text is insufficient.

## Latest refinement: small tasks inline, large audiences controlled

**INLINE FIRST.** A small set of choices belongs next to its explanation. The knowledge popup and its Choose information / Save selection / Back to campaign sequence are removed. Responsive cards show the three choices horizontally where they fit and stack on phones. The selected count updates immediately and the choices persist in the saved draft and final review. The selected count makes no automatic-save claim; explicit Save draft persists it in this isolated browser preview. Production must use its real persisted draft/save behavior and communicate save failures accurately.

**CLOSE ONCE, BACK WHEN THERE IS A REAL PREVIOUS VIEW.** Root dialogs use the accessible X, Escape on web and native sheet dismissal. Do not add Back to campaign beside Close merely to dismiss the same root view. Nested views retain Back to their actual list or preceding form. An edited dialog still protects unsaved inputs; a real campaign exit still offers Keep editing / Discard changes / Save draft & leave. A dedicated full-page tool still needs an explicit campaign return. Preserve keyboard focus on the initiating control. The file-preview flow keeps Back and Approve in the footer, with Save for later approval as a secondary body action.

**500 PEOPLE MUST NOT CREATE 500 ROWS IN THE PAGE.** Timing initially shows selected total, local times known and time-zone holds, plus the default local schedule. Known local time is not a permission verdict. View people & hours expands inline without navigation. Search covers the entire selected audience; status filters prioritize Needs review; mixed audiences also have a destination filter. The current preview renders at most ten people per page, across a responsive two-column desktop list or one-column phone list. Each person opens in place to reveal effective hours, source and hold reason. Pagination and display filtering never change campaign membership. People selection and contained permission review are also searched and paged; selections survive hidden pages. An already-selected person who becomes held can be removed, but cannot be added again while ineligible. The final review and launch check must never mark those people ready.

Use the full available width for audience details instead of leaving an empty side column beside a long list. The Timing page places start and budget together, audience hours across the width, then retries and budget explanation together; phones stack these sections. Native pushed campaign screens anchor the action bar to the safe bottom edge because they have no root tab bar.

**REGIONAL COPY FOLLOWS THE ACTUAL AUDIENCE.** For a domestic Canadian or US audience, explain contact address → supported area-code fallback → common hours if several zones → hold if unknown, without naming another country. For an Indian audience, explain IST and no daylight-saving clock changes; do not show North American examples. For a mixed audience, use neutral shared wording and source/time-zone detail for the actual destinations in that audience. For an unknown country/zone, do not infer a country or legal rule from language or a shared +1 prefix. Hold the call for review. Provider start/expiry controls name the provider’s real zone; recipient rules use the recipient’s destination. Localization controls language, not legal geography. This changes presentation only; PLAN §8 remains authoritative and all country consent restrictions remain in force.

The studio includes **Calling hours · 500 people / US audience / India audience / mixed audience / unknown location** states. The 500-person synthetic fixture has 480 known local times and 20 held for review. A multi-zone example explicitly names both zones and shows only their common permitted window. Indian and mixed fixtures use a service conversation, preserving the promotional restriction. These are isolated design fixtures, never production records, permission grants or scheduler results.

Production acceptance requires business-scoped, bounded server queries with stable record IDs/cursors; server search/filter across the entire audience; authoritative aggregate counts, effective windows and derivation metadata; persistence of selected IDs across pages; stale-result handling; loading/error/retry/empty/permission states; recalculation immediately before dialling; and complete localized wording. Do not fetch the full audience just to paginate in the browser. Do not invent routes or storage fields; Phase 1 supplies the actual rule/data contracts under AUT-1 and its documented schema discipline, Phase 4 reconciles them, Phases 4–5 bind and verify the surfaces, and Phase 6 checks end-to-end behavior. **No decorative controls, stubs, fake counts, guessed provenance or toast-only integrations satisfy any phase.**
