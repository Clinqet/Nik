§6 — Caching contract (you confirmed this — kept here as the reference)
THE CACHE CONTRACT confirmed
QuestionAnswer
What is cachedEach section/filter combination's response (cards + counts together, from one response — a cached page is internally consistent). At most 10 combinations; oldest dropped. Browser memory only — zero server memory.
How long60 seconds fresh, then stale-while-refresh: within 60s a flip renders from memory with no call. After 60s it still renders instantly, but silently re-fetches and swaps in the fresh result.
What clears it instantlyEvery mutation (approve / update / dismiss / edit / mass / bulk — success or failure) · any re-run · a document finishing processing (existing live signal) · workspace switch · leaving the page.
The teammate edge caseA teammate approves on their phone while you look: your list can be up to ~60s behind. Acting on a card they already handled gets the server's honest answer ("already approved" / "not found"), a toast, and a reload. A stale read can never cause a wrong write.
Slow-response edge caseA response landing after you switched sections is dropped entirely — not rendered, not stored. A mutation does the same to any read already in flight, so an approved card can never be restored to life by a reply that left before you pressed it. Errors are never cached. "Show more" pages append into the same entry.
MobileIdentical contract, same session.
