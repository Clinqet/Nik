A"What should we call you?" — provider web

Shown once, right after any sign-in, when either half of the account's name is still our team's stand-in ("Guest" / "User") and the owner has taken the account over. Never during a team setup session. The fields are filled with any half that is real; a stand-in is never shown as a value. Save writes the name; Not now (or the ✕, or Escape, or a tap outside) closes it and it asks again after 7 days. On a laptop and an iPad it is a centred card over the dashboard; at phone width it rises from the bottom.

A"What should we call you?" — provider phone app

The same question as a native bottom sheet over the dashboard: slides up, drag handle, blurred backdrop, rides above the keyboard, respects the home-indicator area. Swiping it down or tapping outside is the same as Not now. A light tap on Save, a success buzz when it is saved, an error buzz when it is not — the app's existing haptics helper.

C"Your business profile is ready" — customer web

Someone opens the customer site's Register, types a name, an email and the phone number our team used for a business. The form is replaced by this step; one tap sends a code to that phone and opens the normal code screen. The name they typed is carried along so that, when the code opens the business account, that name becomes the account's name.

How the name travels (N4). The first and last name from the register form are held in memory only — React state handed to the code screen, never the browser's storage, never the address bar — and sent with the code check as the optional proposedFirstName / proposedLastName. The server uses them only when this code check is the one that hands the business over; on any other sign-in they are ignored. A name it cannot accept (digits, "@", a web address, over 100 characters) is quietly ignored — it never stops the sign-in; the name question (A) then asks later. Note for the build: the customer site keeps the phone details in SessionStore.set("loginData") today; the name must not join them there. If the person closes the tab before the code, the name is gone and A asks later — the safe outcome.

C"Your business profile is ready" — customer phone app

The same step in the customer app's own look: the picture background, the green panel, the pill button the customer app uses. The name typed on Register travels to the code screen as a navigation value (memory only — never AsyncStorage or the Keychain).

One wording choice for the owner (it does not block the build). Both customer apps already ship this step (commit 38b5887 "Prepared provider accounts, take-over, and services with no price": clinqetwebuserapp/components/auth/PreparedProfileReady.jsx, clinqetmobileuserapp/src/components/PreparedProfileReady.tsx), so the note in REMAINING-WORK-2026-10-06.md P1-2 that they "do not handle the 409" is out of date. Their title today is "This number already has a business on Clinket". This sheet draws the title this brief asked for, matching the provider apps: "Your business profile is ready on Clinket" — a change of words in one existing key per app (×5 languages, table D). The body, the button and the link stay as shipped. What N4 really adds to the customer apps is the name carried into the code check.

RRules the build must keep

  • When it asks: after a sign-in, only on an account that has been taken over (ClaimedAt set), only while either half is a stand-in, never in a team setup session, never more than once per 7 days after "Not now". Decided from the profile the apps already read — no new request on every page.
  • Save uses the existing PUT api/v1/UserProfile with the names only. ‼️ It must not change the marketing choice: the "null means keep" fix in SOLUTION §14.3 ships first.
  • Never shown as a value: "Guest" or "User" in any case. A real half is always prefilled exactly as stored.
  • ✕, Escape, tap outside, swipe down = Not now. Saving cannot be abandoned mid-request.
  • Same words, same rules on provider web and the provider phone app, shipped in the same change; both customer apps shipped together.
  • Icons only from each app's set: provider web lucide-react (X, Loader2, WifiOff, AlertCircle, Menu) + react-icons in the toast; provider phone Ionicons (alert-circle, cloud-offline-outline, person-outline, search-outline, share-social-outline, notifications-outline, chevron-down); customer web react-icons (FaShieldAlt, AiOutlineCloseCircle) + its own arrow SVG; customer phone FontAwesome shield.
  • Check in the browser at 320, 375, 768, 1024 and 1440 before calling it done; phone apps on a small and a large simulator, light and dark theme.
