3 · Rules

  • The count comes from the server (readingProgress on the document's own record: stage, done, total). The screen never estimates or animates a number of its own.
  • Pages vs pictures: pages first, then pictures — the same order the reading does them. A very long page counts as ONE page and completes when all of it is read (no word like "section" is ever shown).
  • No count yet (the first moments, or a short file that finishes in one go) ⇒ today's row exactly (state A). Short files never show a count at all.
  • The count only moves forward, and only when that part is saved, so leaving and coming back never shows a smaller number.
  • Polling keeps today's short ladder that ends (the approved rule); the count is simply read with the row.
  • Read again on F re-reads the file; the text and the 60 pictures already described are reused, so only the pictures that now fit cost anything.
  • States G and G2: one page ⇒ its number; several ⇒ how many. Provider setup (the assistant chat) ends its closing message with the same sentence. Raising the limit and choosing Read again reads only what was cut short.
  • State H uses the existing reason and the existing notification — the provider is told once, never again for the same reading.
