Email shell

One frame for every Clinket email. A message says only its own words; the frame supplies the logo, the font, the colours, the phone layout and the footer — so a message cannot be modern in English and broken in Hindi, and nothing has to be copied from the last email somebody wrote.

Every frame below is the real output, generated by the code that sends the mail, shown on a computer and on a 375px phone side by side.

  • Headings and the words that matter
  • The one thing to do
  • The facts of the thing
  • It went well
  • Something to act on

Facts + footer link

The commonest shape: a greeting, a sentence, a details box and the quiet footer. The details box is where a provider looks first, so it is a panel and not a run of sentences.

Status chip + success facts + a supplied block + button

The chip names the moment, the green facts box is what changed, the offer block is composed by the biller and dropped into a row of its own, and the green button is the one thing to do.

en / SubscriptionTrialEnded_Plan

Panels and a list

A grey panel for the facts of the sign-in and an amber one for the thing to act on. Amber is only ever used for something the reader must do.

en / LoginNotification

Two supplied blocks

The invoice lines and the Pay now button are both composed by the invoice sender and dropped in as blocks; the shell gives each its own padded row.

en / InvoiceEmail

Plain paragraphs only

Most messages are only sentences. They declare paragraphs and nothing else, and still get the frame, the font and the phone layout.

en / MfaCodeNotification

No heading at all

Eleven messages have never shown a heading. Inventing one would change the words, so the shell simply leaves it out and the sentence stands alone.

en / NoShowClaimReminder

Button plus a plain link fallback

The link appears twice on purpose: as the button, and written out underneath for a reader whose client blocks the button.

en / ServiceDetailsEmail

Hindi — the longest words we ship

Hindi and Gujarati run longer than English. The button goes full width on a phone rather than being given a fixed size, so a longer label can never be cut off.

Hindi facts on a phone

On a phone each label sits above its value instead of sharing the row, because a translated label and a date cannot both fit on one line at 375px.

Sub-headings and bullets

A longer message breaks into sub-headings and lists. Both are part of the shared frame, so they look the same in every message that uses them.
