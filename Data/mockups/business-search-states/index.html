The states the first sheets did not draw

Eleven states of Ask Clinket that no approved mockup covers yet, web and phone. Every one is reachable in normal use, and each is drawn from what Clinket can actually tell the member — not from what would be convenient to draw.

00 What is already settled, and not re-drawn here

Three sheets are approved and stand unchanged: the page and its core states (provider-ai-search.html — empty, running, answered, nothing found, error, permission denied, daily limit, plus header Option A), how a source appears (business-search-sources — one card per file type, Show page N / Show text, and no download anywhere), and the microphone (business-search-voice — eleven mic states and the correction chip). This sheet adds only what is missing — and §01b corrects M1's suggestion chips.

One rule behind all eleven

Every state below says what happened and what to do next. There is no spinner that ends in nothing, no empty panel, and nothing that reads as a finished answer when it is not.

Where the server sends the sentence, the screen renders the server's sentence — it is already translated and already carries the number. The screen invents copy only for what the screen itself does: the empty state, the buttons, the panel chrome, offline, and the cut-short notice on a replayed conversation.

01b The "Try asking" chips — the provider's own, never generic

A chip is a promise. "What is our cancellation policy?" shown to a plumber with no documents spends one of the day's questions and returns "I couldn't find anything" — the screen caused that. So a chip is only ever offered when it cannot dead-end, and two of them are built from the provider's own catalogue, so a salon is asked about a HydraFacial and a plumber about a drain survey.

Built on screen, from what the app already has — no new request, no AI

The service names come from the same catalogue list the dashboard already loads and keeps. All ten roles can read that catalogue, so every member gets their own business's words. Nothing is generated, nothing is guessed, and the sentence around the name is a translated template with the name dropped into it — so it reads correctly in all five languages.

04 Keyboard open — the rule, stated

The box docks, it does not float

The ask box sits flush on the keyboard, full width, with the mic and Send in it. It is the same control in the same order as the idle state — nothing moves position when the keyboard appears.

The answer scrolls behind it, anchored to its last line

Opening the keyboard keeps the bottom of the answer in view instead of leaving the reader in the middle of a table.

Chips, Recent and Sources are hidden while it is up

They live below the fold behind the keyboard, so drawing them claims a reachable control that is not. They come back the moment the keyboard closes.

05 An answer that was cut short

Six things can end an answer early: the model's own length cap, the answer budget, the clock on the whole question, the daily spend guard, the number of look-ups one question may make, and the member pressing Stop or closing the tab. In every one the words already written are kept — and marked.

Live as it is being written

Cancellations inside 48 hours are charged at 50% of the quoted value, and the deposit is not returned when

This answer was cut short. Ask a narrower question to see the rest.

This sentence comes from Clinket, already translated. The screen shows it because it was told the answer was cut short — never by reading the words themselves, which would only work in English.

Reopened later replayed conversation

Cancellations inside 48 hours are charged at 50% of the quoted value, and the deposit is not returned when

This answer was cut short. Ask it again to see the rest.

A saved answer that ended early is stored with a hidden mark on it. The screen removes the mark and shows its own notice. Leaving the mark in would look like gibberish; leaving it out would present half a policy as the whole of it.

The one new copy key on this sheet "Ask it again to see the rest" — the live sentence tells the member to narrow the question, which is advice about a question they are no longer asking.

06 A document this member may not search

A document can be restricted to certain roles. The correct rendering of a restricted document is no rendering at all — it is absent from the answer, absent from the sources, and its pictures do not appear. Nothing tells the member it exists. What they get is an honest answer built from everything they can see.

The staff-pay document exists and is restricted to the owner. It is left out before the assistant is given anything, so there is no "restricted" badge to draw, no count of hidden results, and no way to work out from the answer that the document is there. A badge would be the leak.

‼️ Two different facts, two different sentences. "I couldn't find anything" is about the business's information. "You don't have access to that" is about this person's role — a fixed server sentence, with no figure fetched first and no record or person named. Rendering one as the other is the defect this pair exists to prevent.

What is deliberately NOT drawn: a "some results were hidden" line. It would tell a member the restricted document exists, which is exactly what restricting it was for. Where an answer is genuinely narrower than the whole business — a search that failed, or a language it could not read — the assistant says so in its own words, inside the answer. There is no separate message for it, so the screen must not invent one.

10 What this settles

No state is silent, and no state is a spinner

Eleven states, eleven sentences. Each says what happened and what to do next.

Restricting a document draws nothing

Absence is the rendering. A badge, a count of hidden results, or a "restricted" note would announce the very document that was restricted.

A cut-short answer never looks finished

Live, the screen is told the answer was cut short rather than reading the words. Reopened, it removes the hidden mark and says the same thing in its own words.

Nothing offers a file, anywhere

The page-unavailable state has no "open the original" fallback, because that route was removed. A missing page falls back to the wording already on screen.

Reopening never spends a question

Recent replays a stored exchange. When the exchange has expired the question goes back in the box and waits for the member.
