2 · Web — Knowledge page, default state
Two blocks: Documents and FAQs. Every document shows its type, what it's linked to (optional), size facts, and a live status chip. Statuses flip automatically — no refresh button needed, no manual steps.
Status-chip color semantics (D33, owner-reviewed): green = Ready · blue + spinner = Processing (calm, automatic — the spinner is the "working" signal) · red = Failed · amber = true warnings only (limit reached, knowledge space full). Processing is deliberately NOT yellow/gradient: amber reads as "needs your attention" in this design system (same reasoning as the platform's access-denied state, which is info-navy, not amber), and a gradient fights the flat pill language used across all four apps. Brand green #97EF29 stays reserved for pressed/selected/CTA. Every color on this page is the house token set (navy #032858, green #97EF29/#F4FFE4, info #E4EEFB, warn #FFF7E8/#9A5B00, danger #B3261E/#FCECEA, borders #E7E7E7) — verified against the existing mockup system; no new colors introduced.

Build notes (not visible to providers): upload = SAS direct-to-blob (portfolio pattern) → confirm → queue → one function does extract (Document Intelligence prebuilt-read; txt/md skip it) → chunk → embed (text-embedding-3-large) → index (new clinket-knowledge-{region} index on the existing search service). Deterministic card ids make redeliveries and replacements idempotent; delete purges cards + registry + blob. Rev 2026-08-18: a table card stores the same label: value | label: value text it embeds (no markup — storing HTML while sizing on plain text put 83% of live cards over their own ceiling and returned 2 passages instead of 5); every budget excludes the prefix the card carries; row groups pack to the target while the oversize-row split stays on the hard max so a wide record is never stranded without its id. Provider-facing wording is "searchable parts", never "passages". The searchable-space cap is now visible as a second counter and is checked BEFORE upload — it used to be enforced only after extraction had already been paid for. Statuses arrive via the standard list refresh; no polling UI needed beyond the natural page load. §0.7 approval table (index, registry record, container, queue, settings) is presented at build kickoff.
