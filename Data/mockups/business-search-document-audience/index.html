5 · The roles — the business's own, and why two are missing

What the picker shows
Operations managerSales representativeDispatcher TechnicianCatalogue managerFinance ContractorRead-only auditor …any role this business added
‼️ Owner and Administrator are not chipsThey can find every file whatever this is set to — that is what the line under the choice says, and it is enforced on the server. Drawing them as chips would let a provider untick "Administrator" and believe an administrator had been shut out. They have not been, and cannot be.

M1 §4 drew them as chips, and drew them ticked. This sheet supersedes it on that point only.
Where the names come fromEvery name is the platform's own word for that role — the same word the team screens show, in the reader's own language. Nothing here is typed into this screen.
What happens to the setting when roles change
What happensWhat the provider sees
A colleague is given one of the picked rolesThey can find the file straight away. Nothing to re-save.
A colleague loses one of the picked rolesThey stop finding it. Nothing to re-save.
A role the business added is deletedThe chip is simply gone from the picker; the file keeps its other roles. The mark on the row counts what is left.
Everyone leaves but the ownerThe box stops being drawn — a one-person business again — and the setting is kept, not cleared.
Nothing is copiedThe choice stores the roles, not the people. That is why none of the rows above needs the provider to do anything.

7 · What is deliberately not here

Left out on purpose
Not drawnWhy
Picking people instead of rolesA person's access would then have two sources that disagree the moment somebody changes jobs. Roles follow the person; a name does not.
"Preview who can find this"It would list colleagues by name on a file the provider is in the middle of restricting, and it needs a read the editor does not otherwise make.
Setting it while uploadingThe caller switch is chosen at upload because an unshared file must never be sendable for even a moment. Team search has no such moment: the default is everyone, which is what an unmarked file already is.
Changing several files at onceWorth having, but it is a list-screen feature with its own states. Not this sheet.
A record of who changed itThe business activity feed is where that belongs, if it is wanted at all. Adding a line here would be inventing a second history.

8 · Decisions this sheet asks for

1 · Owner and Administrator are not chipsThey always find every file. M1 §4 drew them as pickable and ticked; this sheet removes them and says the rule in one line instead. Supersedes M1 §4 on that point.
2 · The box saves as you tapMatching the caller switch beside it, not the editor's Save button. The editor's Save stays for the file type and the linked work.
3 · "Only certain roles" with nothing picked is allowedIt means you and your administrators, it is said out loud in amber, and it is not blocked.
4 · The mark counts roles, it does not name them"Found by 3 roles", never "Found by Operations manager, Dispatcher, Finance".
5 · The box can be used while a file is still being readUnlike the caller switch, which waits for the file to be ready.
‼️ 6 · CHANGED BY THE P4 AUDIT — "just you" is now "the owner and admins"The mark and the heading pill are read by someone who may look but not change, and that person cannot find a file restricted to nobody. "Found by just you" told them they could. Naming the owner and administrators is true for every reader.
‼️ 7 · CHANGED BY THE P4 AUDIT — the box stays on a one-person business when the file is restrictedSee the corrected frame in §2. Absent on the default; drawn when there is something to clear.
‼️ 8 · CHANGED BY THE P4 AUDIT — every tap is SENTThe first build skipped the write when the tap matched the open document. That document is a snapshot the list only refreshes while something is processing, so on a settled page a deliberate confirming tap became a silent no-op against a value that had changed elsewhere — and the file stayed team-wide. The server compares against the current row and costs no write when it matches; that is the only place the comparison is safe. After every write, success or failure, the screen re-reads from the server.
