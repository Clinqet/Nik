2 · Upload documents — wider web frame, and a row that cannot break

What is wrong today: the row is one wrapping flex line — icon, name, type dropdown, offering dropdown, ✕. At the modal’s 560 px that adds up to more than the available width, so the ✕ falls to its own line on desktop, and on a phone the two dropdowns and the ✕ scatter across three lines. The fix is structural, not just wider: the row becomes two fixed zones — identity on top (name + ✕ pinned right, which can never wrap), controls underneath — and the modal moves to the platform’s existing wide size (760 px), which the shared Modal primitive already supports — no new width is invented.

4 · The dropdown itself — the platform control, not a raw <select>

Both knowledge pickers are currently bare HTML <select> elements, which is why they look nothing like the rest of the product. They adopt FloatingOptionSelect — the app-drawn dropdown already used elsewhere: #F5F5F5 field, floating label, chevron, green border while open, #DFFABD on the chosen row, keyboard arrows + Escape, panel drawn in a portal so it is never clipped by the modal’s scroll area. The one addition is search, added to that shared component so every long list in the product gains it — nothing new is invented here.
