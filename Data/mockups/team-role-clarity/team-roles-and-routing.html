1 · Role detail dialog — what a role really allows, in plain words
Opens from See more on the invite screen, from any role chip on the team list, and from the role chips in the member dialog. The rows are derived from the real permission grants on the server — never hand-written — so they can never drift from what the server actually enforces. The wording is a small fixed set of phrases, fully localized.

3 · Notification routing — redesigned
What changes: (a) the two cards you can actually change come first; the two automatic ones fold into one calm "Always automatic" block at the end — no more locked cards mixed between live ones. (b) "A team" is gone (it could never work — there is no way to create a team anywhere in the product; it errored the moment it was tapped). (c) Two choices instead of three, written as sentences with the consequence spelled out. (d) Naming people is a draft with an explicit Save — nothing is stored until you confirm, and the warning says exactly who will stop getting notifications. (e) The Money card's choice becomes REAL on the backend (today it saves but changes nothing — everyone eligible is still notified regardless).

4 · Every state
Both surfaces, both apps. Empty and limit-reached states don't exist for these screens and are marked N/A with the reason.

Routing · loading

Routing · load failed

We couldn't load these settings

Nothing has changed. This is a display problem.

Routing · not an administrator

Only administrators change this

Who the business tells about new work is set by an administrator. Your own notification settings are always yours.

Routing · solo business (unchanged)

It's just you right now

Everything about this business already reaches you. When you invite someone, you'll choose here who gets notified about what.

Routing · save conflict

Somebody else changed this setting. Reload the page and try again.

The card re-reads the server's truth — the screen never disagrees with the server.

Routing · nobody named yet

Pick at least one person. Until somebody is named, this keeps going to everyone who can handle it.

Save stays disabled at zero people — the server refuses an empty list, so the screen never sends one.

Routing · saving

Both option cards and the picker disable while a save is in flight; no double-writes.

Role dialog · loading / failed

The dialog renders from the role list the screen already loaded. If that list failed, the screen's own error state (with Try again) is showing and there are no chips to tap — the dialog has no separate failure of its own. A chip for a role the list doesn't know (never expected) simply doesn't open.

N/A states

Empty: the role catalogue is fixed at ten system roles and the routing page always has its categories — neither can be empty. Limit-reached: nothing here consumes seats or quota. Shown here so the checklist is complete, not skipped.
