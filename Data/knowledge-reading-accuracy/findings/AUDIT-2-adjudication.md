# Audit 2 — Page-reading adjudication (VisionDocumentTranscriptionService + comparer + verifier), 2026-10-02

Probe `bughunt` (InternalsVisibleTo) drove the REAL service with only transcriber/verifier/rasterizer faked; sources in scratchpad\audit-adjudication (Probes.cs, Harness.cs). VDTS = Services\AI\VisionDocumentTranscriptionService.cs, CMP = DocumentTranscriptComparer.cs, VER = DocumentTranscriptionVerifier.cs, IVER = clinqetcore\Interfaces\AI\IDocumentTranscriptionVerifier.cs.

A–E (live patterns) all reproduce + 16 siblings. 8 classes: rows compared by index/bag-of-words not aligned sequences; a check cannot say "blank"; regions addressed by non-unique labels; one region's refusal discards the page or appends elsewhere; cost bounds drop content; the PDF text layer is never the character authority; the free re-ask overwrites a good reading; "unsettled" not limited to numbers. Every fix changes adjudication ⇒ AdjudicationRulesVersion must rise ⇒ build the raw-output bank first/same deploy.

## Text layer
Whole PDF pages: `RasterizedPage.TextLayer` = PDFium text in content order (DocumentPageRasterizer.cs L156-164, Pdfium\PdfiumDocument.cs L141-158), withheld when ≥80% letters invisible (L399-405). Sections: per box via `PdfTextScope.Box` (FPDFText_GetBoundedText, L165-189). Images/TIFF/scans: empty. Used today only as page-wide word bags letting the machine reading win (Unsettled L1244, WithoutEvidence L1220, Grounded never adds Latin L1131); never given to the comparer (L688), never confirms the AI reading, never tied to a place. Authority design: trust test (visible, shares script, layer text inside DI word boxes matches ≥N% words); rebuild the machine reading's characters from the layer inside each DI cell/line polygon (DI = structure, file = characters ⇒ F85kQ→F8SkQ); settle cell disputes free (layer inside the cell box decides spelling AND emptiness); buy a source check only where the layer cannot decide. Data already in `request.MachineReading.Evidence` (cells with row/col, spans, polygons, words with polygons + confidence).

## Q3 — raw-output bank (design)
Today CachedPage (L1443) stores only decided markdown + policy + review + epoch (reverted page = ""); raw transcripts (both attempts) and raw check answers are not stored ⇒ a policy change re-buys everything. Design: (1) raw bank, blob only, immutable, keyed on INPUTS: transcript attempt `_ocr/{biz}/{doc}/{hash}/raw/{deployment}/t-{sha}.json` keyed on render recipe (page, edge, JPEG quality, quarter-turns, new hand-raised RenderRulesVersion) + model (deployment, effort, max tokens) + SHA of full system + user prompt (incl. quoted reference, partial flag, re-ask quote); value = raw completion, truncated/failure state, usage, epoch. Check answer `.../raw/{verifyDeployment}/v-{sha}.json` keyed on verify render recipe + model + prompts. Optionally reuse per region question. (2) Decision cache = today's CachedPage + AdjudicationRulesVersion; on miss re-adjudicate from raw entries; money only for a raw key that is missing. (3) Two versions §0.23: RenderRulesVersion (rasterizer, Pdfium, PageOrientation) and AdjudicationRulesVersion (comparer, adjudication); prompt edits move raw keys by hash. Inputs reproducible: machine reading (DI bank `{biz}/_di/{doc}/{hash}.json.gz`, picture `di-{hash}`, section `_regions/…` — gaps: bank write skipped above ContentArtifactMaxBytes; drafts re-derive + setup re-buy DI unbanked); text layer recomputed free from bytes; page angle from DI evidence. Images deterministic per PDFium/ImageSharp build ⇒ key on render recipe + RenderRulesVersion, not JPEG hash. Check ceiling must be deterministic (F-21). Storage: blob only under existing `provider-knowledge/_ocr/` and `provider-setup-docs/_ocr/`; purger (KnowledgeDocumentDataPurger L109), closure teardown (BusinessClosureTeardown L218/L224) and lifecycle rule (azureautomation\storage.json L367-389: cool after 50 days, delete after 180) already cover them. No Cosmos/SQL/Search/queue change. Size ~10–30 KB per transcript attempt, few KB per check. Cutover: existing pages have no raw ⇒ first deploy re-reads every page once; land with the rule fixes ⇒ one bump, one re-read.

## Q4 — alerts
Today: Required before every check per page (L844, Medium); Outcome after every check per page (L1050); layout outcome one per pass (L495→L1186, Low, continuations each send their own); oversize warning/page/file (L296, L475, L486); time budget (L407); page transcription failed (L456); check ceiling (L465); page cap/rasterization (L556); token cutoff (VisionPageTranscriber L56); drafts consumer outcome per check (KnowledgeServiceDraftAnalyticsJob L957); setup per check (McpService.cs L1477); forced vision outage (Ingest L1847-1857). 26 alerts ≈ 11 checked pages × 2 + 4 layout. Proposed: ONE outcome alert per document reading, only when a human must act — raised by the consumer that commits (ingest Ready commit, drafts commit, setup service write), built from all reviews (banked + fresh); EventId from flow + business + doc + content hash + reading epoch. Items: value not confirmed (a number no reader and no layer confirmed); content dropped (assembly check diffs both readings' digit-bearing facts + aligned rows vs published); two values for one row/column; consumer action needed (prices withheld, name from check, saved pricing kept). Each item: page, heading, row label, column label, machine/AI/check/layer readings, published value, action. High when a number is involved, else Medium; none when nothing needs a human. Drop Required (structured log + counters), per-page Outcome, layout-only. Keep operational dial alerts (time budget, rasterization/page cap, outage after retries, token cutoff, oversize, check ceiling — cited in the doc alert when it left a value unconfirmed).

Recommended order: raw bank → alignment layer (DI evidence grid, row/cell sequence alignment, consuming covers, block-move prose diff) → check-answer model (Blank/NotOnPage per region, judged against the unit's own span) → text layer authority → write-back into structure (no reverts/appends) → bounds never drop content → unsettled only for digits → outcome-only alert.
